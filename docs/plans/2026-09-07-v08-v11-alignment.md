# Alignment roadmap / 回讲能力对齐规划

Follow-up: [history-driven plan-v8](2026-09-08-history-alignment.md) refines the execution batches. The version slots below remain proposals.

Plan Version: plan-v5. Status: proposal, not implemented versions.
Current public and installed baseline: v0.7.0. v0.8–v0.11 are working version
slots, not a promise that four releases are already justified or built.

方案状态：待对比证据驱动的规划。当前公开与本机基线均为 v0.7.0；
v0.8–v0.11 是候选版本位置，不是已经实现、发布或证明更好的版本。

## Objective / 目标

Recover the useful current collaboration behavior in the portable Skill. Keep
existing governance while comparing, and distinguish source content, model
interpretation, substantive response and observed actions.

把当前有效的协作效果提取到可移植 Skill 中。对比期间保留治理层，分别检查
输入内容、AI 理解、实质回应与实际动作；不以模仿措辞或堆叠规则代替效果。

## Version scope / 版本范围

### v0.8 — Multi-value reception / 多重价值接收

Explicitly retain cognition, reasons, examples, materials and open hypotheses
alongside the immediate request. Separate user-stated content from AI grouping;
do not infer a permanent storage request just because content is reusable.

明确接收当前请求之外的认知、理由、比喻、例子、材料和未决假设。AI 的组织
关系与用户原话区分；“值得保留”不自动变成持久写入授权。

Acceptance: mixed input retains all independently identified meaning units,
qualifiers and relations; non-imperative material does not disappear.

验收：混合输入的原子含义、限定和关系可核对，非命令内容不因聚焦任务而丢失。

### v0.9 — Inspectable organization / 可检查的组织与中文语义

Cover received content, interpretation, uncertainty and intended handling when
relevant, without forcing four empty headings. Add Chinese trigger equivalence
and scope tests for readback-first, readback-only and direct-answer requests.

按需要覆盖“收到什么、如何理解、哪里不确定、准备如何处理”，不固定四段模板。
补齐“先回讲／只回讲／直答”等中文表达的等价关系和作用范围案例。

Acceptance: each section serves a real inspection question; corrections and
cross-section dependencies survive; simple input stays simple.

验收：每段解决真实核对问题，修正及跨段依赖不丢；简单输入保持简洁。

### v0.10 — Substantive continuation / 实质回应与动作可核对

Harden the existing v0.7 continuation rule with cases requiring judgment, basis,
recommendation and authorized completion. Separate proposed, started and verified
work. Treat actual tool/action traces as evidence, not claims in a neat receipt.

用需要判断、依据、建议和完成已授权工作的案例强化 0.7 已有规则，而非重复宣称
新增“继续回应”。区分准备、开始和已验证完成；实际工具或动作记录才是行动证据。

Acceptance: the response answers the real request, does not replace judgment with
a questionnaire, and neither repeats execution in a comparison nor invents approvals.

验收：回应实际问题，不把判断推回问卷；对照不重复执行，不把开放选项变成默认决策，
也不凭语义确认制造授权。已获授权的步骤不反复索取许可。

### v0.11 — Deployment evidence / 接入与效果证据

Validate every-turn loading, context reload, missing-Skill behavior and readable
rendering on declared hosts. Compare matched independent sessions if the host
can isolate instructions. Improve adapters only where evidence identifies gaps.

在明确宿主中验证每轮应用、上下文重载、缺失技能处理和可读渲染。宿主能隔离指令时，
再做条件匹配的独立对照；只有发现接入缺口才修改 adapter。

Acceptance: distinguish installation, actual application, response quality and
renderer evidence. No global governance removal is included in this roadmap.

验收：安装、实际应用、回应质量、渲染各有证据。本规划不包含拆除现有治理。

## Execution and release / 执行与发布

Begin with the same-session comparison in the companion protocol. Turn concrete
findings into scoped cases. Each implementation version gets its own reviewed
plan, bounded diff, cases, raw results and release note. Advance by evidence;
merge or narrow proposed slots if they do not represent independent improvements.

先按配套协议做同会话对照，把具体差异转成案例。每个实际版本分别有计划评审、
限定改动、案例、原始结果和发布记录。按证据推进；若不能形成独立改进，就合并或缩小
候选范围，不为了宣传而制造版本数量。

After a version passes its declared release checks, merge it to main and update
the public install path. Separate iteration records must not strand ordinary
users on an older version. Replacing governance is a separate later decision.

每版达到所声明的发布检查后合入 main，保证默认安装取得最新已发布版本。
分版记录不能让用户停留旧版。替换治理层是后续独立决策。
