# Readback First

**位于用户表达与 AI 回答或行动之间的确认层。**

> 自由表达，确认 AI 将要采用的内容。

[English](README.md) · [完整案例](examples/before-after.md) ·
[行为 fixtures](tests/README.md) · Apache-2.0

## 理想中，我们和 AI 的对话，应该很像我们去餐厅点餐

**顾客：**“上次那个双人套餐再来一份，其中一份汤换成玉米汤。我们很饿，能快点上吗？”

**服务员：**“您说的是上次点过的 A 双人套餐：两份牛排、一份薯条、两杯饮料和两份蘑菇汤；这次把其中一份蘑菇汤换成玉米汤，其他不变。对吗？这个套餐正常需要二十分钟左右上齐。”

**顾客：**“菜单对。但二十分钟太久了。最快的是什么？”

**服务员：**“汉堡最快，大约八分钟。可以把两份牛排换成两份汉堡，其他内容保持不变。”

**顾客：**“那就换成汉堡。”

**服务员：**“好的，两份牛排改为两份汉堡；薯条一份、饮料两杯、蘑菇汤一份和玉米汤一份保持不变，预计八分钟左右上齐。对吗？”

**顾客：**“对。”

**服务员：**“好的，现在为您提交后厨。”

餐馆里，服务员在把订单提交给后厨前，会先向顾客复单，确认双方对齐的是同一份订单。

这也是 Readback First 名字的来源：**正式开工前，先回讲。**

## 什么是 Readback First？

Readback First 是一个在 AI 回答或行动前，让用户表达与 AI
准备据此工作的**可见理解**完成对齐的 Skill。

它不声称读取模型全部真实内部理解，也不是思维链查看器。它让 AI
把准备采用的事实、要求、理由、限定、修正、歧义和未决内容讲回来，
供用户检查和纠正。

## 为什么需要它？

用户不应该先成为 Prompt 工程师，才能把真实想法告诉 AI。

大段自由表达、语音转写、说到一半改口、“还是刚才那个版本”、临时补充条件，
都是正常的人类表达。AI 可能给出流畅、合理、甚至看起来很专业的回答，
却静默遗漏限定语、错误合并观点、把候选当成结论，或依据错误理解开始行动。

问题不只在于“用户说了什么”，还在于：

> 用户与 AI 是否已经对齐了 AI 准备采用的内容。

## 同一份输入，两种结果

```text
用户：
“把发布改到周一——等等，公开日期先别改。
周五只保留内部 Beta。不要给客户发邮件。
价格还没有决定。”

没有 Readback First：
“我会把公开发布改到周一，保留周五 Beta，
暂停客户邮件，并增加价格复核。”

有 Readback First：
- 公开发布时间：继续未确认；周一的修改已经撤回
- 内部 Beta：周五
- 客户邮件：不要发送
- 价格：仍未决定，不能擅自变成“安排价格复核”
```

[原始输入 → 合理但错误的处理 → 回讲 → 用户纠正 → 确定输入](examples/before-after.md)。

## Skill 能做什么？

- 在整理前保留源输入；
- 展开事实、请求、理由、条件、限定语、修正、新问题和未完成内容；
- 显示歧义、疑似遗漏和低置信度术语；
- 保留修正与 supersession 关系；
- 在需要时让用户确认源信息覆盖，而不是只确认摘要；
- 把语义接收确认、事实真实性确认和行动授权分开；
- 对简单、已收束请求使用一句回讲或直接出口，避免无限确认。

它不是：

- 思维链查看器；
- 语音识别或转写引擎；
- 普通总结 Prompt；
- 对用户陈述真实性的证明；
- 写文件、发消息、付款、push 或 publish 的行动授权。

## 安装

在 Codex 中请求安装：

```text
$skill-installer install https://github.com/KO2048/readback-first
```

或者手动 clone：

```bash
git clone https://github.com/KO2048/readback-first.git \
  ~/.codex/skills/readback-first
```

安装后重启 Codex。

## 快速使用

```text
Use $readback-first.

接下来我会自由描述一个产品修改。
请保留修正、限定、未决问题和疑似遗漏；
在输入完成对齐前，不要开始行动。
```

也可以自然地说：

```text
回答前先回讲一下。
```

## 核心流程

```text
自由表达
  → 原始输入保全
  → AI 可见工作理解
  → 歧义、遗漏与修正关系
  → 用户纠正或确认
  → 确定输入
  → 与风险匹配的独立授权
  → 回答或行动
```

必须保留的边界：

```text
语义接收确认
  ≠ 事实真实性确认
  ≠ Agent 行动授权
```

## 测试

```bash
python3 tests/validate_fixtures.py
```

公开 fixtures 覆盖未授权压缩、中途封口、修正覆盖原文、候选升级、
限定语遗漏、擅自补全意图、只确认摘要、未解决项消失、确认范围越权、
直答绕过权限，以及对简单请求的过度阻塞。

## 当前状态

`v0.1.0` 是协议与 Skill 首发版。

本版不包含语音识别、桌面输入法、插件、外部行动或在线服务。
语音输入是重要的后续应用场景，不是本版已经具备的能力。
